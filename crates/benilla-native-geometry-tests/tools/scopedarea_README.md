# Exact-source bounded raw VMap area-info oracle

This authored oracle covers loaded static `VMapManager2::getAreaInfo` only.
It does not establish `TerrainInfo` selection, `WMOAreaTable` lookup, terrain
fallback, indoor/outdoor classification, liquid status, gameplay admission,
source authenticity, or actual installation geometry. No installation assets
are used. In particular, raw area metadata must not be taken from the selected
`LocationInfo` instance.

Regenerate offline against CMaNGOS Classic
`8ec338a1704e7dcb1c0213eb7ed58f9231ade40f`:

```sh
python3 crates/benilla-native-geometry-tests/tools/scopedarea_generate.py /path/to/mangos-classic
python3 crates/benilla-native-geometry-tests/tools/scopedarea_generate.py /path/to/mangos-classic --check
python3 crates/benilla-native-geometry-tests/tools/scopedarea_generate.py /path/to/mangos-classic --check --sanitize
```

`--check` compares generated bytes without replacing fixtures. `--sanitize`
enables `float-cast-overflow` with recovery disabled, including the inherited
wet-liquid fixture reconstruction. It is not a complete memory or undefined
behavior sanitizer suite.

## Unchanged original source execution

The generator reuses the whole-file SHA-256 guards and source extraction in
[generate_vmap_fixture.py](generate_vmap_fixture.py), plus the existing
[location source guards](scopedlocation_source_hashes.sha256). No source hash is
weakened or changed. Original `BIH`, `WorldModel`, `ModelInstance` and G3D
translation units are compiled unchanged. The source-exact extracted methods
include these raw area entry points:

- `AreaInfoCallback`
- `StaticMapTree::getAreaInfo`
- `VMapManager2::getAreaInfo`
- `VMapManager2::GetMapTree` and `convertPositionToInternalRep`

The original `AreaInfo` declaration and initialization come from the guarded
`MapTree.h`. Original `ModelInstance::intersectPoint`,
`WorldModel::IntersectPoint`, `WModelAreaCallback`, group point/ray intersection,
BIH point traversal and transformation arithmetic execute without replacement.
The harness substitutes only unrelated core ownership/loading infrastructure
with a minimal manager declaration and map-pointer storage populated from
authored models. The types-only core header substitution is unchanged from the
existing fixture harness.

Every TSV expectation is returned by an actual original manager call. A
subsequent original `GetLocationInfo` query independently audits equal
floor/ADT values and counts metadata differences; it does not supply any raw
area expectation. The additional trace calls original instance methods both
with isolated `AreaInfo` objects and with a shared accumulator, and checks that
the latter reproduces the original manager result.

The generator reconstructs and byte-compares 36 existing products: the six
base numeric native products, dry-location native products and TSV, and
wet-liquid native products and TSVs. Existing source fixture files are never
rewritten. Temporary query hooks add raw manager calls to the existing
authored location/liquid samples without changing their geometry, original
queries or outputs. The existing ray/height TSVs are left untouched rather
than regenerated by this tool.

## Authored products and traversal distinction

[scopedarea/forward](fixtures/vmap_source/scopedarea/forward) and
[scopedarea/reverse](fixtures/vmap_source/scopedarea/reverse) each contain one
tree, one tile and six models. Original model/group/liquid writers,
`ModelSpawn::writeToFile` and `BIH::writeToFile` serialize the numeric input.
The tree/tile framing is the existing authored fixture framing. No original
native parser is invoked.

The two directories have byte-identical model files and placement tiles,
including all model-array indices and spawn IDs. The only difference is the
map tree's leaf object permutation. The original BIH builder is asked to put
the twelve authored placements in one valid leaf; reversing that leaf's
object list independently reverses query traversal without changing loading
order, geometry or bounds. Existing base/location/liquid fixtures additionally
exercise ordinary source-built multilevel map trees.

The six models provide:

- Differing-height floors with different root/group IDs and flags
- Equal-height floors with different metadata and ADT IDs
- Multiple groups including equal-height group candidates and an empty group
- High-bit root/group IDs, high-bit group flags and high-bit 16-bit ADT IDs
- Identical dry/wet geometry and metadata with a numeric `LIQU` payload only
  in the wet model
- An M2 placed alone and above overlapping WMO geometry

Placements also include nonzero yaw, pitch and roll; scales 1.75 and 0.5;
and vertical translations. Cases cover exact/adjacent floor bias thresholds,
instance/group bounds, empty-space gaps, signed zero, no floor below the point,
no loaded map, and world-coordinate binary32 rounding. All fixture names pass
the existing player source-package member policy; model files end in `.vmo`.

## Raw source behavior

The original source intentionally remains uncorrected in this oracle:

1. A successful `WorldModel::IntersectPoint` overwrites shared root ID, group
   ID and flags, even if that instance is lower than a previously found floor
2. `ModelInstance::intersectPoint` updates floor and ADT ID only when the
   reconstructed world floor is strictly higher
3. Therefore metadata comes from the last successful instance, while floor/ADT
   comes from the first instance attaining the highest floor
4. Inside each model, a strictly smaller group ray distance wins; equal group
   distances retain point-traversal order
5. M2 instances and unsuccessful model intersections do not overwrite area
   metadata. A final miss leaves every caller output unchanged

For the authored internal point `(0,0,7)`, forward traversal visits spawn 900
(floor 6) and then 901 (floor 2). The manager returns floor 6 and ADT 33025
from spawn 900, but root `0xf2222222`, group `0xe2222222` and flags
`0x40002000` from spawn 901. Reversing only leaf order keeps floor/ADT unchanged
and returns spawn 900's root `0xf1111111`, group `0xe1111111` and flags
`0x80002008`.

At `(30,0,7)`, both candidates have floor 6. Forward traversal returns ADT
33027 from spawn 902 and metadata from spawn 903; reverse traversal returns
ADT 33028 from spawn 903 and metadata from spawn 902. These are mixed
provenance outputs, not a single selected location tuple.

At `(60,0,7)`, the original nontrivial group BIH selects the equal-height
group `0xe4444443`, with flags `0xc0008000`. Reversing map traversal leaves
that model-local group selection unchanged.

## Fixture contract and verification

[scopedarea.tsv](fixtures/vmap_source/scopedarea.tsv) contains 14,795 rows:

- 675 base cases
- 1,357 existing dry-location cases
- 5,511 existing wet-liquid cases
- 3,626 forward and 3,626 reverse traversal cases

The original manager returns 8,382 hits and 6,413 misses. The harness checks
all five output arguments bit-for-bit on every miss, observes 499 metadata
differences from the independent location result, and checks 14 exact dry/wet
parity pairs. Fourteen parity pairs include both hits and misses.

Columns are declared in the TSV header. `kind` identifies the native fixture
directory, with `base` meaning the parent `vmap_source` directory. Coordinates
and `z_out` are eight hexadecimal binary32 digits. Flags and IDs are decimal
unsigned 32-bit raw patterns, including negative original `int32` ID sentinels
and high-bit original root/group IDs. ADT on success is the widened source
`uint16`; on a miss its full caller-provided sentinel is unchanged. Map 0 is
loaded, while map 1 exercises the original missing-map result. The private
consumer's stricter map-identity gate remains a separate contract.

[scopedarea_trace.tsv](fixtures/vmap_source/scopedarea_trace.tsv) contains 18
original point-traversal traces. It records the actual source-converted
internal point, all map callback spawn IDs, successful spawn IDs, and each
successful instance's isolated floor/ADT/root/group/flags in callback order.
Comma-separated lists retain traversal order; `-` denotes an empty list.

Generation, byte-for-byte `--check`, and `--check --sanitize` passed on Linux
x86-64 with C++17, no fast math, no contraction and round-to-nearest. Cross-
platform and real-asset validation remain separate. No Cargo build or test is
part of this standalone oracle generator.
