# Selected private terrain production

This original local adapter ports the **selected-tile terrain and Classic MCLQ liquid** branches of CMaNGOS
Classic `ad -f 0` at `8ec338a1704e7dcb1c0213eb7ed58f9231ade40f`.
It reads the player's own Data directory, owns exact raw input buffers, writes
`MAPS` / `z1.4` terrain, and has a separate app adapter into the existing
`TerrainTile` reader. It does not generate VMaps/MMaps, import world-content rows,
construct gameplay capabilities, install providers, or activate NPC startup.

## Packaged inspection on Windows

Matching player downloads include `benilla-native-terrain.exe` beside `benilla.exe`.
From PowerShell in the extracted player folder, use your existing Classic Data path:

```powershell
.\benilla-native-terrain.exe --data "C:\Games\World of Warcraft\Data" --map 0 --tile 48,32 --inspect
$LASTEXITCODE
```

No Rust toolchain, player configuration change, or output directory is required.
The selected pair contains the existing Northshire meeting position; it does not
prove a complete playable Northshire closure. Keep patchers/updaters closed and
leave Data unchanged while inspecting. Inspection runs the same bounded source
capture, exact patch-winner comparisons, writer and fresh-input checks as export,
then discards generated bytes in memory. It never publishes artifacts. This is
producer readiness only: the standalone helper does not invoke the app's separate
`TerrainTile` consumer or install a gameplay provider.

On success the exit code is zero, with map/tile, source epoch, product size and
SHA-256, `live_install_lease=false` and `gameplay_admitted=false`. On failure the
nonzero exit and bounded `error[diagnostic.id]` identify the refused stage without
printing local paths or raw input names. Unknown errors use a generic identifier.
Report only those IDs, map/tile and hashes; never upload Data, generated products,
or asset-containing logs. Inspection needs no cleanup. For export, remove only
the explicitly chosen generated folder using your file manager's recoverable
trash/recycle operation; leave the installation and player state untouched.

Actual Northshire acceptance remains unverified. Classic MCLQ is supported when
all serialized liquid heights are determined by the selected tile. A rectangle
that needs an unwritten outer-edge height rejects with `terrain.liquid_history`;
malformed framing or unsupported later-client liquid data also rejects. These are
possible failures, not a claim about the first failure in a real installation.
Do not remove patches or modify assets to force success. Both this writer and the
terrain reader support nonflat float heights and the supported liquid output;
the separate continuous gameplay corridor proof still requires flat dry ground
and rejects liquid-bearing terrain products.

## Read-only JSON diagnostics

When inspection fails, the helper can retain the independent checks and bounded
numeric observations in one JSON object on stdout:

```powershell
.\benilla-native-terrain.exe --data "C:\Games\World of Warcraft\Data" --map 0 --tile 48,32 --diagnose
```

`--diagnose` creates no files and cannot be combined with `--output` or `--inspect`.
It uses the same selection limits, bounded archive reader, exact patch-winner
checks, staged discovery comparisons and writer validation as inspection. Only the
one through nine explicitly selected tiles are read; no predecessor or full-world
scan is attempted. It does not recover missing history or admit gameplay.

The envelope has `format: "benilla-terrain-diagnostic"`, `version: 1`, numeric
`map`, `map_table`, `source_epoch`, `stages`, `tiles`, and the two always-false
`live_install_lease` / `gameplay_admitted` fields. A valid invocation exits zero
when the report was emitted, even if validation failed. Read each stage's
`status` (`passed`, `failed`, or `unavailable`) and `diagnostic_id` (a fixed safe
identifier on failure, otherwise null). Malformed arguments still exit two with
a bounded path-free diagnostic on stderr.

- `map_table`, when validated, contains zero-based `selected_row_ordinal` and
  `total_rows`; it never includes a map name or directory
- Top-level stages are `selection`, `initial_capture`, `map_table`,
  `selection_capture`, `full_capture`, `area_table`, `liquid_table`, and
  `source_recheck`. Independent table checks still run if another table fails
- Each selected tile contains `x`, `y`, `raw_adt` (captured byte count `bytes` and
  `sha256`), `active_mclq_cells`, `liquid_rectangle`, `missing_liquid_heights`,
  and stages `wdt_selection`, `adt_structure`, `liquid`, `production`
- Liquid observations come from the shared validated writer scan. The rectangle
  has numeric `x`, `y`, `width`, `height`. Missing serialized heights have `count`
  and the first row-major `first_x`, `first_y`, or null coordinates when count is
  zero. Flat output consumes no height payload, so its missing count is zero
- Unavailable or inapplicable observations are null. A dry tile has null liquid
  observations. A failed dependency leaves its dependent stages unavailable;
  failure in one tile does not suppress independent checks of another selected tile
- `source_epoch` exists only after an actual complete selected-member capture and
  staged discovery comparisons. It may accompany a writer or later recheck
  failure; it does not establish a live source lease or successful production

Only counts, coordinates, hashes, booleans and fixed schema/diagnostic identifiers
are emitted. No local paths, member names, raw errors, liquid height values or
asset strings are included. Raw ADT hashes describe captured bytes, including when
ADT validation fails; they are not a certificate of valid terrain.

## Local command

`--output`, `--inspect` and `--diagnose` are mutually exclusive. The output parent must exist. Choose a fresh directory outside the entire client
installation. Terrain grid coordinates are explicit: `32,31` reads ADT
`<directory>_31_32.adt` and writes `maps/0003231.map` for map zero.
The numbers below are a command example, not a claim of supported real terrain.

```sh
cargo run -p benilla-native-terrain -- \
  --data "/path/to/WoW/Data" --map 0 --tile 32,31 \
  --output benilla-config/private-terrain
```

Repeat `--tile` for an explicit closure of at most nine tiles. No tile or neighbor
is silently added, skipped or truncated. A terrain collection is not a corridor
coverage certificate. Source members, generated files and manifests stay private;
never commit or upload them. The command has no network or asset download path.

The CLI creates generation artifacts. The separate app `SourceTerrainProducts`
consumer validates them through the existing terrain reader before retaining the
selected decoded tiles; neither path constitutes movement/support authority.
The full rendered collision and generated VMap/MMap closures remain separate.

## Inputs and honest source identity

The fixed DBC inputs are complete `Map.dbc` (42 fields), `AreaTable.dbc` (25),
and `LiquidType.dbc` (4), followed by the selected map's WDT and ADT members.
Map selection and WDT MAIN selection derive filenames; no arbitrary MPQ path
or imported audit declaration determines output identities.
Map ID and directory come from fields zero and one. Complete table framing,
unique map IDs, every directory's string offset, terminator and UTF-8 decoding,
and the pinned extractor's 64-byte name storage remain checked for every row.
Only the selected directory becomes a path and must be nonempty ASCII letters,
digits, underscores or hyphens. Bounded empty or special names on unselected rows
do not trigger path validation, lookup or extraction for those maps. Their bytes
still participate in the complete consumed-member epoch and fresh-input checks.

Map-selection diagnostics do not print directory strings or paths:
- `terrain.map_directory`: the selected directory is empty or has unsupported
  path characters
- `terrain.selected_map_metadata` or `terrain.unselected_map_metadata`: the
  indicated row category has an invalid string reference or UTF-8, or a name
  longer than 63 bytes (the terminating NUL must also fit the source's storage)
- `terrain.map_missing`: the selected ID is absent
- `terrain.duplicate_map_id`: any map ID appears more than once

The field selection and all-row storage bound follow `ReadMapDBC` at
`contrib/extractor/System.cpp:189–208`; upstream constructs paths later in
`ExtractMapsFromMpq:858–879`. This helper constructs only the selected map's paths.

Benilla's normal patch chain and pinned `ad` are **not identical resolvers**.
This adapter accepts only the conservative intersection: every consumed member
must have the same exact winning archive basename and complete bytes under
Benilla's bounded chain and the pinned `ad` fixed order
`model.MPQ`, `dbc.MPQ`, `terrain.MPQ`, `patch.MPQ`, `patch-2.MPQ`.
For each fixed archive, the accepted header is the first `MPQ\x1a` signature
on a 512-byte boundary within the existing one MiB scan budget. Raw versions zero
and one are supported; their declared header sizes are interpreted as 32 and 44
bytes respectively, including protected nonstandard values, without changing any
source bytes. Version one must contain the complete 12-byte extension, with its
64-bit extended block-table position and both 16-bit high table offsets all zero.
This follows `contrib/extractor/mpq_libmpq.cpp:27` and
`dep/libmpq/libmpq/mpq.c:59–164` at the pinned source. A first unsupported header
cannot fall through to a later one. The bounded Benilla reader must retain the
exact same base and extension bytes from the same handle used to decode its
index, at the same selected offset; a later path reread cannot supply provenance.
The ordinary unbounded app reader is unchanged and does not validate or retain
these extension fields. User-data pointers alone do not establish compatibility:
a pointer at offset zero to an unaligned header at 16 is rejected; a pointer
selecting a different aligned header is rejected even when selected members have equal bytes.
The declared archive size must still equal all bytes from the selected header to
EOF. Index offsets are relative to that header and checked against that exact
length, with the normalized 32-byte or 44-byte minimum, disjoint spans, nonzero
power-of-two hash count, 64 MiB index budget and 64 KiB sector limit. Raw versions
two and above, nonzero extended fields, trailing bytes beyond the declared
archive, and arbitrary archive-size normalization remain unsupported.
Selected-member framing is unchanged.
Absent fixed archives are allowed as upstream does; ambiguous casing, tombstones,
missing/dummy members and different winners fail. An extra winning patch is not
silently ignored even if its bytes match. The policy is versioned in the manifest
and source-epoch digest. No external extractor executable is invoked.

All complete member bytes, winning identities and policy are retained immutably.
Discovery captures must match the final capture. Fresh-chain rereads before and
after generation and before manifest publication reject observed changes. This
is an immutable **consumed-buffer epoch**, not an atomic filesystem snapshot,
lock, hostile-ABA defense, proof of client build authenticity, or live installation
lease. The manifest explicitly says `live_install_lease: false` and
`gameplay_admitted: false`. A later native session still needs a genuine source
lifecycle contract; hashes alone cannot hold an installation fixed.

## Header inspection diagnostics

`--inspect` reports a bounded path-free diagnostic line on failure and a path-free
summary on success. Neither outcome writes files.
Header checks precede index decoding, and fixed identifiers distinguish:

- `source.ad_header_signature`: no signature on a scanned 512-byte boundary
- `source.ad_header_truncated`: a selected header has fewer than its required 32 or
  44 bytes
- `source.ad_header_scan_limit`: discovery would exceed the one MiB budget
- `source.ad_header_version`: the first selected header has raw version two or above
- `source.ad_header_extension`: a version-one extended block-table position or high
  table offset is nonzero
- `source.ad_header_selection`: Benilla and the pinned extractor select different
  offsets or header bytes
- `source.ad_archive_size`: the declared length differs from bytes after the header
- `source.ad_sector_size`: sectors exceed 64 KiB
- `source.ad_hash_count`: the hash count is zero or not a power of two
- `source.ad_index_budget`: encoded hash and block tables exceed 64 MiB
- `source.ad_index_spans`: table spans overlap, precede the normalized header, or
  extend beyond the declared archive

These replace the former combined `source.ad_header_profile` diagnostic. Share
the identifier and build ID when reporting a failure; no installation path or
archive content is needed. A supported header does not by itself prove terrain
coverage or permit gameplay. The source-resolution policy is version three; the
complete consumed-member bytes and exact winner comparisons are unchanged.

## Writer fidelity and restrictions

The source references are `contrib/extractor/System.cpp`: Map loading 189–208,
AreaTable loading 211–233, LiquidType loading 235–254, `ConvertADT` 291–837,
and WDT selection/filename ordering 840–879. Raw framing follows `adt.h` and
`wdt.cpp` at the same pin. The independently extracted source oracle records
full source hashes and extraction intervals under `tools/fixtures`.

- MCIN slot row/column controls placement, not the MCNK's advisory ix/iy fields
- Row-major later cells overwrite shared V9 seams, resetting base before adding
- Binary32 height addition, V8-then-V9 extrema scans, source +/-20000 initial
  extrema, -500 minimum clamp, and exact-flat omission are preserved
- `-f 0` never applies the near-flat threshold or integer height packing
- AreaTable physical row order, duplicate last-wins, uint16 narrowing, unknown
  area `0xffff`, uniform/full AREA layout, V9-before-V8 output, and the complete
  512-byte hole block are preserved
- Classic MCLQ visibility compares the whole byte to `0x0f`; visible bit `0x80`
  contributes deep water. MCNK water/ocean/magma conditions independently add
  flags, with the last condition determining the entry. Every active cell writes
  all 81 heights, including invisible and untyped cells, in MCIN order
- MLIQ type layout, cropped visible bounds plus final vertices, source extrema
  seeds, hidden interior `-500` writes, and exact `-f 0` flat omission are preserved

### Liquid history boundary

The upstream converter does not clear its global 129×129 liquid-height array
between tiles or maps. Hidden packing writes cover only the interior 128×128;
serialized row/column 128 can therefore depend on earlier conversions. This
producer tracks current-tile writes explicitly and requires every emitted height
sample to be known. It does not import a prior `.map`, assume a fresh-process zero,
or treat tile request order as upstream extraction order. No height ownership is
needed when no liquid section or `NO_HEIGHT` is emitted. The oracle runs identical
selected inputs after different complete source conversions, checking both stable
admitted bytes and different history-dependent outputs that Rust refuses.

The manifest uses writer policy `cmangos-ad-f0-selected-tile-owned-liquid-v2`.
This is an expanded, explicitly bounded writer profile, not universal wet-tile
coverage. Later support for rejected histories would need exact predecessor inputs
and source traversal, including earlier cross-map writes and conversion failures.

The bounded parser requires canonical MCIN placement, all 256 distinct referenced
MCNKs, source-relative MCVT when present, finite supported heights and strict framing.
A genuine zero MCVT offset preserves the source base-only height branch; dangling
references reject. Classic MCLQ records use complete 812-byte framing or an
8-byte empty record; an inner declared size of zero is resolved using the bounded
MCNK extent. Missing MCLQ and sizes at most eight take the source skip branch,
even with class flags. Active consumed heights must be finite. An all-hidden tile
with nonzero liquid types rejects rather than executing upstream's invalid bounds
branch. Later-client MH2O representations, global-WMO maps, incomplete tiles,
unknown structural chunks and resource overflow remain unsupported. Normal render-model placement
records may coexist: their presence does not prove their collision dependency
closure. Terrain generation does not prove absence of dynamic participants.
The exact restrictions and diagnostics are executable tests, not fallback flags.

## Publication and limits

At most nine selected tiles; 64 MiB per raw member, 192 MiB aggregate captured
members, 64 bounded archives and bounded MPQ indexing/decompression. Output paths
are derived only from checked numeric map/tile IDs. Files are private on Unix,
created without overwrite and synced. Products are reread and compared before a
complete, synced manifest is atomically exposed with a no-replace hard link.
Failure/crash can leave an incomplete fresh directory; retry with a new output,
never infer completion from file presence alone. Directory sync is Unix-only;
Windows file sync does not imply directory durability. A failure after the complete
marker is linked reports `output.published_but_durability_unconfirmed`; the complete
marker may already be visible and no rollback or successful durability is claimed.
No previous export is
replaced, and no output is automatically activated.

## Evidence and remaining acceptance

Tests use only original authored MPQ/DBC/WDT/ADT data. The source oracle compiles
isolated pinned source routines/readers with authored local-file transport; it
neither builds nor runs the external `ad` executable. Byte-level comparisons,
source-change and publication failures, and actual `TerrainTile` decoding are
separate gates. No player installation was available for this checkpoint.
A player-local run against a real selected tile is still required; it may report
unsupported source geometry. Passing authored tests is not Northshire acceptance.
