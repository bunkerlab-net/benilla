# Authored installed-source corridor test

This test-only fixture joins the existing consumed-source compatibility observation
with an actual loaded Bevy/Avian local corridor. It does not install a production
world or convert a conditional navigation terminal into a Route.

The authored archive contains nine canonical, placement-free guard ADTs and a
separate exterior ADT retaining the strict emitting WMO and its complete model
closure. The exterior object remains in the full raw inventory and source map.
Only the guard assets are resident. A distinct feature-gated guard installer keeps
the existing whole-map-empty installer unchanged; it installs real loader output,
terrain colliders, streamer state and the original full inventory in the index.

In one synchronous immutable ECS read scope, the test obtains provenance from the
actually installed NativeStaticMapIndex, checks consumed-source compatibility,
queries actual source heights and a source ray, derives the raw geometry revision
from actual live coverage, and invokes unchanged LocalCorridor certification.
It checks the same owner and source freshness again before returning. No copied
source revision substitutes for the independently derived raw coverage revision.
These sequential filesystem observations do not promise future source stability.

The guard plane lies below the captured exterior WMO's vertical bounds. This is
important: original BIH vertical traversal skips parallel X/Y root clipping, and
source height selection can retry a long downward search. Distant XY bounds alone
cannot justify ignoring an unloaded slot. Source fixture assertions retain a
crossing-Z Missing case; neither reader traversal nor Missing semantics changes.

The ordinary live checks remain required: complete canonical 3×3 assets, exact raw
digests, dry/flat continuous support, full collider identity and membership,
exterior exclusion, body overlap/sweep and elevated line of sight. Same-content
replacement inventory cannot reuse an earlier owner's compatibility observation.

The dedicated CI step selects the exact positive test and requires one executed,
passing test. Until that test actually runs successfully, static review and the
non-Bevy source fixture checks do not establish the combined physics result.
Real-install and normal-session admission remain separate work.
